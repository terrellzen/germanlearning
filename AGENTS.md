# Working on Stillwort

## Product and implementation

Stillwort is a static German learning application for GitHub Pages. Use React, TypeScript, Vite, and Tailwind CSS. There is no backend, authentication, analytics, spaced repetition, or persistent study history. Keep collection discovery manifest-driven and respect Vite's base path for every asset and JSON fetch.

The visual direction is Apple-inspired: black and white, neutral grey surfaces, system sans-serif typography, restrained rounded cards, and blue primary buttons. Preserve both light and dark themes, visible focus states, reduced-motion support, and layouts down to 375px. Do not add green, beige, multicoloured collection badges, or serif display fonts.

## Vocabulary and examples

- Preserve the four original Anki `.txt` exports in `data-source/` byte-for-byte. Do not invent forms, infer conjugation persons, or change supplied meanings during unrelated edits.
- `data-source/general-examples.csv` holds authored German examples keyed by stable vocabulary sense IDs. Preserve its `id`, `german`, and `english` columns when editing example sentences.
- `data-source/example-translations.csv` holds English translations keyed by the exact German sentence. Update both sides if a German sentence changes; do not attach a stale translation to revised text.
- Irregular-verb and preposition German examples come from the original exports. Preserve them. Reviewed preposition field boundaries live in `scripts/mappings/preposition-meanings.json`.
- Run `npm run import:vocab` after source changes. A single collection can be imported with `npm run import:vocab -- --collection irregular-verbs` (other IDs: `a1`, `a2`, `prepositions`). Generated application data in `public/data/` must be committed.
- The editable combined CSV is generated by `python3 scripts/convert_vocab.py`. Editing a generated CSV alone does not update the website. Keep `example_de` and `example_en` in spreadsheet exports.
- Render imported text as escaped React content. Do not inject HTML.

## Learning behaviour

Keep card generation, sequencing, and monotonic timing in the engine/hooks, separate from rendering. Never advance through unseen phases after a delayed timer callback. Pause on hidden-page visibility changes and remain paused on return; do not pause on window blur, since the app must keep running on a visible second monitor.

For translation exercises, show the question-language example with the question and reveal the answer-language example with the answer. Reverse both when switching direction. Keep conjugation examples hidden until reveal if they could disclose the tested form. The examples toggle must affect both sides without resetting the card, timer, or pause state.

Random order must show every card once per cycle, avoid identical boundary repeats when possible, and preserve the actual Previous/Next history. No permanent learning history or review ratings.

## Checks and deployment

Use Node.js 22.12+ and the committed npm lockfile. Run:

```sh
npm ci
npm run validate:vocab
npm test
VITE_BASE_PATH=/germanlearning/ npm run build
```

For visible UI or playback changes, run `npm run dev` on port 5173, install Playwright Chromium once with `npx playwright install chromium`, then run `npm run test:browser`. An existing browser executable can be supplied with `CHROMIUM_PATH`. For a hosted build, set `BASE_URL` to its full URL. Inspect desktop and mobile screenshots, and verify both themes when changing styles.

Source lives on `main` at `terrellzen/germanlearning`. After committing source changes, use `npm run deploy:pages` to publish a verified build to `gh-pages`. The Actions alternative lives in `deployment/github-actions.yml`; enabling it needs GitHub workflow permission. Keep the GitHub Pages publication configuration documented in README.md. Verify successful deployment and the public manifest/assets before claiming the site is live. Never commit credentials, local translation models, `node_modules/`, `dist/`, browser screenshots, or generated ZIP download bundles. Do not force-push or rewrite remote history as part of routine updates.
